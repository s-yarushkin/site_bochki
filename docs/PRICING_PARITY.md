# ДачаПар — единый контроль цен: калькулятор → Комфорт → сайт → квиз

**Статус:** обязательный контракт для любой публикации/изменения цены. Редакция 31.10.2026.  
**Это единственное нормативное место в репозитории для процедуры сквозной сверки цен.** Отдельные документы про комплектации, сайт и квиз описывают свои сценарии, **но не заменяют этот контроль**.

## 1. Главное правило

**Нельзя менять опубликованную цену только в одной системе.** Любое изменение цены, размера, базового состава или формулы должно пройти цепочку:

```text
Google Sheets: РРЦ / Методика / 01 · Цена Комфорт
             ↓
Google Sheets: Прайс R90 · все модели — 20 опубликованных Комфорт
             ↓
GitHub: web/data/catalog-pricebook.json (prices + r85.models.*.sizes.*.priceRub)
             ↓
Расчёт сайта (r85-pricing.mjs / quote.mjs), таблицы HTML, главная, сравнение, JSON-LD
             ↓
Google Sheets: Квиз · быстрые цены — 41 планировка (база + комнаты + печь)
             ↓
Будущий квиз сайта — только тот же базовый прайс и проверенные коэффициенты
```

**Живой финансовый источник — [ДачаПар_калькулятор](https://docs.google.com/spreadsheets/d/1tDbbyKBW5opBRLWk_twPTryKYm9wgaezEcI5hTla06o/edit).** Снимок в GitHub служит **тестовым контрактом, не вторым коммерческим прайсом**. Внести новую цифру в снимок, чтобы обойти тест, **нельзя** без сверки живой Google-таблицы и согласования владельцем.

### Идентификаторы

- Модели: `kvadro`, `viking`, `parus`, `kvadro-house`.
- Длины стандартных корпусов: `400`, `450`, `500`, `550`, `600`; Квадро Хаус: `4x4`, `5x4`, `6x4`, `6x5`, `6x6`.
- В схемах Квадро Хаус визуальные размеры `4×5`, `4×6`, `5×6` нужно явно сопоставлять с кодами сайта `5x4`, `6x4`, `6x5` соответственно. **Нельзя** менять соответствие одной системы, не проверив другую.
- Коды планировок: `DP-PL-001`…`DP-PL-041`, зеркало имеет **тот же** код. Исходник — [альбом v04](https://docs.google.com/presentation/d/1SCetq_5FtJrlr1ckeUpS3U9iUVBexamV3KDuTyuDKhA/edit).

## 3. Как верифицировать 20 цен «Комфорт»

Для каждого из **20** вариантов:

```text
Google Sheet «01 · Цена Комфорт»: S38:S57
  == Google Sheet «Прайс R90 · все модели»: D4:D23
  == web/data/catalog-pricebook.json: prices[model][size]
  == web/data/catalog-pricebook.json: r85.models[model].sizes[size].priceRub
  == calculateSelection(..., package="comfort").basePrice
  == цена на странице модели в HTML
  == цена в JSON-LD / Offer
  == стартовая цена на главной и в сравнении, где применимо
  == Google Sheet «Квиз · быстрые цены»: E13:E53 (для 33 схем с известной базой)
```

Прайс сайта не может «догнать» калькулятор просто за счёт правки текстов. Если хоть одно равенство нарушено — **BLOCK / NO DEPLOY**. Исключение: **8 широких корпусов 6×3**, для них базовая цена отсутствует, в квизе и предложении **`null` / «Стоимость уточним»**, а не цена узкого корпуса.

**Контроль 31.10.2026:** все **20/20** базовых цен совпали между Google Sheets и `catalog-pricebook.json`, включая `r85`. **33/33** базовых цен планировок квиза совпали с моделью/размером; **8/8** широких корпусов не имеют числовой цены. Видимые цены из HTML модельных страниц, главной и страницы сравнения включены в новый репозиторный тест.

## 4. Квиз: формулы, которые нельзя менять отдельно

Текущие коммерческие правила утверждены владельцем **только для упрощённого подбора**, в листе [«Квиз · быстрые цены»](https://docs.google.com/spreadsheets/d/1tDbbyKBW5opBRLWk_twPTryKYm9wgaezEcI5hTla06o/edit?gid=202610314).

```text
base = Comfort[model][size]
extraRooms = max(0, roomsInPlan - roomsAlreadyInComfortBase)
roomSurcharge = extraRooms × GoogleSheetQuiz!B7     // 13 540,50 ₽ за комнату
stoveSurcharge(1–2 guests) = 0                     // штатная Термофор Оса
stoveSurcharge(3–4 guests) = GoogleSheetQuiz!B8    // ASTON 12, +7 000 ₽
stoveSurcharge(5–8 guests) = GoogleSheetQuiz!B9    // ASTON 16, +12 000 ₽
preliminary = base + roomSurcharge + stoveSurcharge
```

- ASTON 12/16 — с **открытой и закрытой каменками и стеклянной дверцей**; техническая совместимость проверяется по объёму парной и монтажу, не по числу гостей.
- В цене Комфорт уже учтена штатная **«Термофор Оса»**, не начислять полную стоимость ASTON заново.
- Структурное правило для дополнительных комнат: Квадро / Парус / Викинг — **2**; Квадро Хаус форматы `4x4 / 5x4 / 6x4` — **3**; `6x5 / 6x6` — **4** (принятая для квиза калькуляторная база; фактический заводской состав согласуется).
- В расчёте **нет** полной стоимости сантехники, душа, мебели спальни, кухни, изменения печного узла, доставки. Поэтому рассчитанные цены **предварительные, не договорные**, нельзя рекламировать их как «всё включено».
- Подбор и визуализация: [бизнес-спецификация](quiz-selection-and-pricing-2026-10-31.md), [дизайн-спецификация](quiz-ux-design-2026-10-31.md).
- **Не путать** цену базовой модели на сайте и **стоимость конкретной планировки**. Текущий код `web/r85-pricing.mjs` помечает добавочные помещения выбранных схем как требующие согласования и имеет свой критерий `rooms > (bundle.roomCount || 2)`, что **не полностью совпадает** с внутренней базой 3/4 помещений Квадро Хаус. При таком расхождении нельзя обещать, что `total` калькулятора сайта совпадает с предварительным квизом. Базовые `Comfort` совпадают; окончательную цену планировки ещё предстоит выстроить.

## 5. Единый автоматический контроль в репозитории

### Офлайн-тест — против зафиксированного снимка из Google Sheets

```bash
npm run test:pricing
npm test
```

`tests/pricing-parity.test.mjs` сравнивает:
- **20** базовых цен `Comfort` с `web/data/catalog-pricebook.json` и результатом расчётного движка;
- **20** строк цены «Комфорт» на четырёх страницах моделей и **20** JSON-LD офферов;
- **4** стартовые цены на главной, **15** сумм в таблице сравнения;
- **41** строку квиза с правильной моделью, размером, комнатами и **0/7 000/12 000 ₽**, без цены у 8 широких корпусов.

**Единственный тестовый снимок**: `tests/fixtures/pricing-parity-2026-10-31.json`. Он создан по **живым Google-данным 31.10.2026**. Это страховка репозитория, но если кто-то изменил **только** Google Sheets, локальный тест этого сам не узнает.

### Обязательный предрелизный тест против текущей Google-таблицы

```bash
npm run test:pricing:live -- /путь/к/свежей-выгрузке-Google-Sheets.json
```

Файл **должен быть подготовлен из свежего чтения двух листов через авторизованный Google Sheets API/подключённое приложение**, а не копированием `tests/fixtures/pricing-parity-2026-10-31.json`. Нормализованный JSON для команды содержит те же ключи и структуру `comfortPrices`, `quizPlans`, `quizRules` (см. снимок). Скрипт проверит все значения **на равенство текущему репозиторному контракту** и вернёт код ошибки при любом расхождении. Если выгрузка не предоставлена, **команда `test:pricing:live` завершится ошибкой**.

**Автоматический запуск в GitHub:** [\`.github/workflows/pricing-parity.yml\`](../.github/workflows/pricing-parity.yml) запускает `npm run test:pricing` при изменениях сайта, тестов, скриптов и конфигурации. Команда `npm run release` также запускает этот тест в `scripts/build-release.py` **до сборки пакета**. GitHub Actions не получает доступ к Google Sheets сам по себе: его PASS не заменяет свежую авторизованную сверку.

**Это отдельное ручное/авторизованное действие перед релизом.** В текущем GitHub нет постоянно подключённых прав на чтение приватной Google-таблицы из CI, поэтому **не утверждать, будто Google Sheets автоматически синхронизируется с GitHub**. При наличии сервисной авторизации можно позже автоматизировать свежую выгрузку.

## 6. Порядок любого изменения цены

1. **Изменить и согласовать источник** в Google Sheets (`РРЦ`, `Методика`, `01 · Цена Комфорт`). Проверить расходы, производство, маржу и округление. Не редактировать `Прейскурант` как самостоятельный источник.
2. Проверить **20 строк** `01 · Цена Комфорт!S38:S57` ↔ `Прайс R90 · все модели!D4:D23`. Неутверждённые строки **не выходят на сайт**.
3. Сверить и синхронно обновить **обе** цены в `catalog-pricebook.json`: `prices` и `r85.models.*.sizes.*.priceRub`, а также связанные версии/контракты защищённого API и сохранённых ссылок. Не менять API/прайс без согласованной процедуры релиза.
4. Обновить **HTML/SEO**: главную, четыре страницы моделей, сравнение, JSON-LD и все другие текстовые ценовые блоки, если они затронуты. Устранить возможность независимого ручного изменения.
5. Пересчитать 41 строку [квиза](https://docs.google.com/spreadsheets/d/1tDbbyKBW5opBRLWk_twPTryKYm9wgaezEcI5hTla06o/edit?gid=202610314). **Не писать цену квиза отдельным хардкодом**: базовая сумма определяется тем же `Comfort`, а новые комнаты и печи — сверенными параметрами B7:B9.
6. Выполнить **свежее чтение** Google Sheets, сформировать новый нормализованный снимок и **сверить** его с репозиторием. Обновить тестовый снимок в одном контролируемом коммите после подтверждения изменений. **Само обновление снимка не является проверкой.**
7. Запустить `npm run test:pricing`, `npm run test:pricing:live -- <экспорт>`, `npm test` и штатные регрессионные тесты/проверки `python scripts/check-public.py`. Любая ошибка или отсутствие свежего экспортного файла — **NO DEPLOY**.
8. После выкладки провести реальную **публичную** проверку цен сайта (включая API и CDN-кэш) и квалифицированную проверку нескольких конфигураций в интерфейсе. **GitHub parity PASS сам по себе не доказывает, что production обновлён**. По завершении зафиксировать версию и время проверки.

### Условие «ничего не менять»

Если нет утверждённой новой цены, **не требуется** обновлять публичные цены или квиз. Контроль выполняется read-only. Проверка не имеет права молча исправлять продажи или подставлять «ближайшую похожую цену».

## 7. Позже — цены конкретных планировок (отдельный этап)

**Сейчас** в прайсе есть 20 цен базового Комфорта; **нет** 41 утверждённой конечной цены оснащённых планировок. Схемы и отдельные комнаты — основание для **предварительного** расчёта, не окончательного оффера.

Когда будут полностью согласованы печи, сантехника, мебель, состав помещений и широкий корпус 6×3:
- утвердить спецификацию и стоимость **каждой** из 41 планировок (`DP-PL-xxx`) вместе с комнатами и вариантом комплектации;
- добавить отдельную таблицу `approvedLayoutPrices` со статусом согласования; сохранение кода на основной/зеркальной схеме;
- расширить **тот же** `tests/pricing-parity.test.mjs`: `Google утверждённая планировка = репозиторий = цена на сайте = цена в квизе` плюс проверки, что зеркальный вариант не меняет цену;
- на этапе перехода удалять устаревшую предварительную формулу только после утверждения новой. **Ни одна неподтверждённая стоимость не публикуется под видом финальной**.
