# V74 — «Дача Пар»: продуктовая переработка клиентского пути
**Статус:** утверждённый перечень замечаний + детальная постановка для нескольких ролей; реализация НЕ начиналась. **Основа:** production V73, commit `34a370a3daac5b742a93806c29effa542fccdef8`, 19.10.2026. **Тип работ:** новый единый релиз V74; не hotfix и не изменение действующей V73. **Владелец продукта:** утверждает цену, тексты, фотопакет, планы и финальную приёмку.

## 0. Северная звезда продукта
Посетитель должен за первые секунды понять **что продаётся (готовая баня для дачи)**, **почему баня продумана**, **что уже входит в стоимость**, **как выглядит выбранная конкретная модель**, **сколько будет стоить проверенная конфигурация** и **какой следующий шаг**. Продаём готовый результат и чувство отдыха; не показываем устройство внутреннего каталога, себестоимость, переменные программ, номера опций и технологические оговорки без функции для покупателя. Доказательства и честность важнее декоративной «магии»: визуал не может обещать несуществующую комплектацию.

## 1. Решения, которые уже приняты
1. На сайте показываем **коммерческую стоимость бани с шагом 5 000 ₽**, не произвольные рубли из внутреннего калькулятора. Точный контракт — [PRICE-CONTRACT.md](PRICE-CONTRACT.md). Рабочая экономика/закупочные значения остаются закрытыми. **Запрещено** округлить только DOM, оставив серверную цену другой.
2. Никакой скрытой и самостоятельной «распродажи», зачёркнутой фиктивной цены, скидки, якобы подтверждённой экономии. Скидочный механизм — будущий цикл, отдельное одобрение владельца.
3. Сначала проверяем компоновку и тексты; отдельный дизайнер позднее готовит реальные/достоверные изображения и варианты отделки. До утверждения изображений визуальный конфигуратор может демонстрировать только достоверные состояния/планы. Не выдумывать геометрию бани.
4. **«Квадро» — существующий визуальный ориентир узнаваемого реального объекта**, но даже его материалы подлежат проверке. Для «Парус», «Викинг», «Квадро Хаус» нужна новая арт-дирекция.
5. Единый продуктовый V74 собирается только после независимых PR, сквозной проверки браузера, цен, заявок, SEO, менеджерского кабинета и безопасной rehearsal/cutover.

## 2. Состав замечаний → задачи → измеримый результат

### V74-01 · Первый экран desktop и «виртуальные экраны» [P0, первая работа]
**Наблюдение владельца:** в первом экранном кадре видны заголовок «Приехали на дачу. Растопили баню. Отдых начался» и фотография, но **нет CTA** `Собрать свою баню` / `Посмотреть модели`. Схема `01 Изготовление на производстве / 02 Доставка или сборка / 03 Отдых на даче` также уходит ниже. При уменьшении окна внезапно видимых элементов становится больше.
**Техническая гипотеза, не подтверждённая до измерений:** избыточные верх/низ padding, сетка `.hero-grid`, высота изображения `.hero-image`, margins `.hero-proof`, breakpoints по ширине без media query по высоте, размеры H1 и действительные показатели `visualViewport`. Нужно снять вычисленные значения, не «чинить» наугад.
**Обязательная функциональная модель:** header + hero с H1, коротким смысловым описанием, фото, двумя кнопками и тремя шагами полностью видны **без прокрутки** на desktop baseline 1366×768 (100% zoom) и на 1440×900, 1536×864, 1920×1080, если нет пользовательского увеличения шрифта. Для 1280×720 допускается компактная схема, но главная CTA обязана быть видна; для малых мобильных высот не жертвуем чтением/доступностью ради «одного экрана». Первые CTA должны иметь размер, контраст и работать клавиатурой.
**Виртуальный экран ≠ CSS scroll-snap на весь сайт:** виртуальный экран — законченная смысловая секция с читабельной композицией, ясным назначением и собственной точкой действия/перехода. На длинных разделах допускается естественная прокрутка; никакого жёсткого `height:100vh`, вырезающего блок, forced scroll snapping, скрытого текста или ломания zoom.
**Секция-инвентарь:** hero; проблема/ценность; каталог; базовая комплектация; атмосферная интерлюдия; «Комфорт»; индивидуальная комплектация; доставка; конструктор; сравнение; FAQ; финальный CTA; футер. По каждому указать цель, следующий шаг, признак лишней вставки и ограничения высоты.
**Файлы:** `index.html`, `assets/css/site.css`, `assets/css/weather-v6.css`, `assets/css/mobile-cta-v2.css`, `assets/css/mobile-layout-audit.css`; новый `tests/browser_v74_first_viewport.py`; `docs/v74/artifacts/01-hero/...`.
**Приёмка:** на согласованной матрице screenshot + JS bounding boxes H1, 2 CTA, 3 proof; viewport-relative `bottom <= innerHeight - safe margin`; нет горизонтальной прокрутки; 100/90/110% zoom, sun/rain, без навигации только мышью. Скрины `before/after` попарно одинакового размера.

### V74-03 · «Найдите свою баню»: связка цены и базы [P0]
**Наблюдение:** в карточках есть `Базовая комплектация от` / цена; отдельная ниже расположенная плитка из 19 позиций выглядит оторванно и неровно. Клиент не понимает, что баня уже укомплектована.
**UX-решение к проектированию:** карточка: цена и явное действие `Что входит в стоимость`; при нажатии показать компактное модальное окно/drawer с общим базовым составом **и модельно-специфичными уточнениями**, затем прямой путь «Выбрать Квадро / модель». Отдельный большой блок «Что входит» оставить, но связать через одинаковый визуальный язык и якорь. Цена как интерактивная кнопка допустима только с доступным названием и очевидной affordance; не делать число ложной ссылкой. Список базы не обещает чужой модели центральный вход «Квадро» или арочный «Викинг».
**Удалить** фразу «Цена от — ориентировочная стоимость выбранной вами базовой комплектации». Вместо оборонительного дисклеймера — положительное объяснение: «В стоимость входит готовая баня в базовом оснащении. Доставка, разгрузка, основание и необходимые работы на участке оплачиваются отдельно» (точную редакцию утверждает владелец). Нельзя утверждать универсальную бесплатную сборку.
**QA:** 4 карточки → база для выбранной модели → выбор в builder, включая mobile/keyboard; не зависят от фото; корректно считаны цены всех размеров; никаких внутренних ставок/дублирующихся доплат.

### V74-04 · Контент, ценность, редакторская чистка [P1]
**Наблюдение:** промежуточный атмосферный блок «Солнце на участке. Впереди — время для себя» и «Баню подготовят заранее. А способ доставки подберём…» может прерывать продажу и повторять hero; встречается техничка «дополнение по каталогу».
**Задача роли редактора:** инвентаризировать ВЕСЬ видимый текст, включая aria-label, модальные окна, кнопки, ошибки формы, SEO, менеджерские тексты, вариант sun/rain, `data-v6-sun/rain`. Для каждой фразы сохранить / укоротить / переписать / убрать + причина, задача секции, факт, который подтверждает текст. Удалить или перепроектировать skyline-вставку по аналитическому решению (без её удаления вслепую). Запрещены `позиция каталога`, `дополнение по каталогу`, `DEMO_ONLY`, `нет утверждённой цены`, типовые технические комментарии в публичных блоках.
**QA:** поиск по DOM и исходникам на запрещённые маркеры; экспертная проверка со скриншотами, индексируемые SEO-страницы не должны потерять релевантные ответы.

### V74-05 · Типографика / логические переносы [P1]
**Наблюдение:** «На фото бани похожи, но / разница в конструкции» разрывает одну смысловую единицу.
**Задача:** карта H1/H2/H3, подсказок, заголовков карточек и цен по ширинам. Для конкретного H2 исправить ритм так, чтобы фраза «Но разница — в конструкции» была синтаксически целой там, где это возможно. Использовать управляемую ширину, `text-wrap:balance/pretty` с fallback, локальные span/точечные non-break; нельзя расставлять универсальные `&nbsp;` или ручные `<br>` в ущерб узким экранам и 200% zoom. Проверять кириллицу, переносы, min-content, выделения em.
**QA:** скриншоты по сетке, при 200% zoom нет обрезки, нарушенного порядка чтения и horizontal overflow.

### V74-06 · Конфигуратор: продуктовая модель и визуальные состояния [P0/P1]
**Наблюдение:** «выбираю 4/5 м, цвет, кровлю и дверь, а баня остаётся прежней»; элементы описаны текстом без изображений.
**Требуется:**
- фиксированная/липкая *зона визуального доказательства*, которая показывает выбранную модель, **подтверждённую** планировку, размер, корпус, кровлю и релевантное изделие; цена обновляется без задержки и не разъезжается с server quote;
- три типа визуальных ответов: **A основной экстерьер** (форма модели, корпус/кровля, крупная дверь при проверенном ракурсе), **B подробная карточка** (полки, ограждение печи, стеклянная дверь, подсветка, окно, форточка), **C компактная подсказка** (мелкая деталь);
- **планы** как технические, утверждаемые производством схемы: размер × модель, геометрия, комнаты, двери, окна, печь, реальные ограничения. При отсутствии достоверного плана — «Планировка уточняется», без псевдочертежа;
- цветовые визуалы только из утверждённой медиаматрицы/детерминированных слоёв; не использовать CSS `hue-rotate` как будто это точный цвет древесины; если цвет недоступен — явный swatch + пояснение, не выдуманное фото;
- визуализация опций с `id` из pricebook, совместимостью model/size и реальным эффектом. «Стеклянная дверь» может заменять подтверждённую штатную **внутреннюю** дверь; сначала уточнить спецификацию базовой двери у производства; не менять наружную дверь по ложной связи;
- доступность: keyboard, focus, `aria-live` итогов, reduced motion, no layout shifts, alt/captions, latency budget и fallback без JS.
**Граница реализации:** первая очередь — продуктовый UX и фото/план layout c честным fallback; вторая — реакция размеров и цветов по утверждённым ассетам; третья — картографирование и визуализация крупных допов. Не объявлять Full готовым без полного каталога/совместимости/ассетов.
**Файлы:** `assets/js/app.js` (вынести новые визуальные сущности в `assets/js/configurator/`), `assets/js/quote-engine.js` — финансы отдельно, `data/config-visual-manifest.json`, `assets/configurator/`, `tests/v74-*.test.mjs` и browser QA. Схема данных/машина состояний — [CONFIGURATOR-CONTRACT.md](CONFIGURATOR-CONTRACT.md).

Генерация допускается как иллюстративная стилизация только по согласованному прототипу; в репозитории обязателен честный provenance. Не выдавать художественную реконструкцию за документальную съёмку реально изготовленной бани.

**QA:** визуальное утверждение каждым кадром; модели, планы и добавления совместимы; нет битых ссылок, тяжёлых файлов, неверных пропорций, незаявленных конструктивных деталей.

## 3. Границы проекта и обязательные инварианты
- **Нельзя** во время V74 ломать работающий V73, менять его symlinks, SQLite или Caddy до релизного GO. Модуль заявок, защита менеджера, MAX/SQLite, CSRF, cookies и consent остаются безопасными.
- **Нет отдельного «тестового» неправильного расчёта.** `data/catalog-pricebook.json` → `data/pricebook.js`/`quote-engine.js` → relay → SEO/HTML → accepted lead all one version. Логика и UI вместе.
- **Права/источник:** закрытые закупки, комиссии, формулы, цифры себестоимости, личные данные и пароли не попадают в публичный репозиторий, issue, CI output, screenshots.
- **Фото/планы не придумать.** При недостатке материалов задача может завершиться accepted fallback, но релиз полной визуализации блокируется.
- Важно **отделять** продуктовую копирайтерскую правку и регрессионный тест: тест не должен требовать устаревшего внутреннего жаргона или «14 допов» в продающем тексте.

## 4. Порядок выполнения и критический путь
1. **UX/Hero** — снимки baseline, законченный первый экран, измеримые scroll/CTA правила (начинаем немедленно).
2. Информационная архитектура «цена ↔ база», редактура, типографика (можно параллельно после базового UX контракта).
3. Коммерческое округление: owner matrix → pricebook and relay/SEO contract → acceptance.
4. Архитектор визуального конфигуратора определяет схемы размеров/опций и список недостающих media; **без генерации произвольных форм**.
5. Дизайнер и производство поставляют фотографии и утверждённые планы; медиатор валидирует и интегрирует.
6. FE строит работающие A/B/C preview для утверждённых комбинаций.
7. Интеграционная QA-матрица, продуктовый просмотр владельца, единый release candidate, rehearsal, один deploy, post-deploy QA.

## 5. Реестр ролей
- **R0 — Product Owner / Commercial Approver:** цены, приоритеты, одобрение фото/планов/финального hero и слова «от», GO.
- **R1 — UX / Conversion Architect:** CJM, структура виртуальных экранов, первый экран, CTA, связи разделов, проверка на прототипах.
- **R2 — Frontend Layout Engineer:** responsive CSS, измеримость viewport, семантика, доступность, performance.
- **R3 — Pricing & Quote Engineer:** одна коммерческая матрица, rounding, legacy-version reconciliation, relay/SEO, price tests.
- **R4 — Customer Copy / Content Strategist:** инвентарь/редактура, human-language, SEO и UI microcopy.
- **R5 — Configurator Product/Frontend Architect:** state machine, preview/plan/option mapping, media manifest, interfaces & fallback.
- **R6 — Product Media Designer (владелец назначает отдельно):** арт-дирекция и правдоподобные модельные ассеты, согласование с производством.
- **R7 — Media Integration Engineer:** оптимизация ассетов, mapping, загрузка/галереи/вариации, детерминизм.
- **R8 — QA / Release & Safety Lead:** e2e, мобильная приёмка, regression/security, version pin, backup/rehearsal/rollback.
Ролевые входы, выходы, STOP-критерии, каталоги и зоны ответственности подробно в [ROLE-PLAYBOOKS.md](ROLE-PLAYBOOKS.md).

## 7. Definition of Done продукта
V74 не считается готовым, пока не выполнены **все** условия из [ACCEPTANCE-RELEASE.md](ACCEPTANCE-RELEASE.md), включая:
- desktop CTA above-the-fold и 3 шага в целевой матрице;
- коммерческая стоимость кратна 5 000 ₽ и совпадает во ВСЕХ слоях расчёта/хранения/SEO;
- модель/размер/цвет/кровля/значимые опции визуально реагируют **только на подтверждённые данные**;
- фотопакет согласован владельцем;
- «входит в цену» открывается из карточки модели и конкретен для неё;
- нет технических слов и нелепых переносов в клиентских блоках;
- сквозная приемка конверсии, accessibility, SEO, менеджера, auth, SQLite/MAX, backup/rollback;
- owner signoff + immutable SHA + подтверждённый HTTPS после выпуска.
Если хотя бы одна обязательная зависимость не готова — `NO-GO`; допускается отдельная переоценка объёма следующего релиза, но не молчаливое урезание V74.
