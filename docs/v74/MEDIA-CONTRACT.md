# V74 — медиа, фотографии, планы и визуальная достоверность
**Owner:** назначенный дизайнер R6, совместно с Product Owner R0. **Integration:** R7. **Приёмка:** R0+R8. До owner-approval кадры не удалять из production и не делать массовой замены.

## 1. Инвентаризация и принятие решения
Для каждого кадра текущего V73 составить ведомость: `assetId, currentPath, page/selector/slot, modelId, sizeId if known, view, source, provenance, condition, productMatch, problem, replacementTarget, decision[KEEP/REMOVE/REPLACE/SHOOT], ownerReview, sha256`.
Обязательные места: hero обеих тем, четыре карточки каталога, полноэкранная галерея моделей, сцены/слайдер, «Комфорт», 7 шагов builder, SEO изображения, social OG, final CTA. Обложки модели «Квадро» проверить как наиболее близкие к фактическим; остальные НЕ объявлять плохими по модели автоматически, оценить файл и ракурс индивидуально.
Вывод: `docs/v74/artifacts/06-media/media-audit.csv` + контактный лист подписанный именами файлов **в служебных материалах, не поверх коммерческих изображений**.

## 2. Набор кадров по каждой модели
| ID группы | Достоверный обязательный материал | Зачем |
|---|---|---|
| EXT-01 | общий экстерьер 3/4 одной конкретной серийной модели | модельная карточка + gallery |
| EXT-02 | фасад/вход и труба, реальные пропорции | доверие + вход по центру |
| INT-STEAM | реальная парная того же изделия, печь/полки/дверь | gallery + опции |
| INT-LOUNGE | комната отдыха именно этой модели | gallery + хранение/свет |
| PLAN-SIZE | утверждённый производством план каждого имеющегося размера | выбор размеров |
| BODY-COLORS | утверждённые варианты внешней отделки для сопоставимого ракурса | переключение цвета |

Если для конкретной модели/размера нет реального интерьера, **не брать другой**. Для отсутствующего слота — честный fallback и blocker в media coverage; выпуск полной цветной симуляции блокируется до данных.

## 3. Матрица совместимости
Список возможных комбинаций не равен Cartesian product «20 размеров × 12 отделок × 4 кровли». Формируем `modelId,sizeId,finishId,roofId,view,optionId,source/shotId,quality,approval`, только одобренные варианты. Если фото не меняется при другом размере, это допустимо лишь как явно общее изображение модели без лживой привязки к размеру. **Запрещено визуально растягивать реальную баню**, дорисовывать новый фасад/дверь, менять форму крыши или вид из парной ради покрытия.

## 4. Provenance и честная визуализация
- Типы: `real-photo` (оригинальный снимок производителя), `edited-photo` (обработка/ретушь настоящего объекта без изменения конструкции), `verified-render` (модель построена из согласованных заводских размеров), `concept-illustration` (только mood, не якобы реальная изготовленная баня), `verified-plan` (согласованный чертеж).
- Можно создавать качественные, естественно выглядящие иллюстрации, но **не утверждать, что синтетический кадр — документальный снимок реально построенного изделия**.
- Не маркировать производственные фото выдуманным авторством/адресом/датой.
- Внутри manifest происхождение честно и полно, наружу не выводить «ИИ-подписи» или избыточную служебную информацию. Если рендер влияет на ожидания покупателя, доступная подпись «Визуализация выбранной отделки; цвет и исполнение уточняются» допустима и полезна.
- Не наносить текст/лейблы/плашки на сами продуктовые фото; интерфейсные подписи вне изображения. Не генерировать новые формы бань, которых нет в производстве.

## 5. Конструктивные проверки дизайнера перед сдачей
- silhouette точно соответствует модели и штатному входу;
- размер окон/двери, высота дымохода, полки/расположение печи соответствуют реальной спецификации;
- одно и то же изделие последовательно снято внутри/снаружи; не объединять две несвязанные бани;
- правильный вариант крыши, опирание на фундамент/основание, правдоподобные материальные фактуры;
- no extreme HDR, heavy fog, impossible sunlight, synthetic geometry seam, over-sharpening;
- sun/rain styling не подменяет фотографию и не добавляет «дождь по фото»;
- нет на фото конкурента, чужого бренда, недоступной в модели террасы/панорамного остекления;
- права на публикацию исходных материалов проверены; согласие на фотосъемку людей/частной территории при необходимости.

## 6. Передача файлов и manifest
Дизайнер сдаёт **одну версионированную поставку**, в которой есть:
- `README.txt` с номером версии, датой, идентификаторами всех фото;
- `media-audit.csv`, `shot-list.csv`, `approval.csv`, `sha256sum.txt`;
- оригинальные masters под контролем владельца, с исходными разрешениями/версиями;
- web-export WebP/AVIF/JPEG, responsive widths, оригинальный crop reference;
- по каждому кадру `modelId, sizeId, real/edited/render, variant, angle, correspondingPlanRevision`.
R7 после утверждения публикует web-export в `assets/catalog-v74/` / `assets/configurator/`, добавляет записями в `data/config-visual-manifest.json`, обновляет `media-v5.js`/галерею и photo slots без удаления неподменяемых оригиналов. Перед деплоем сверяет SHA и фактические dimensions; image format fallback.

## 7. Приёмка
- Owner смотрит 4 модели, 2 ракурса снаружи, парную и комнату отдыха; под каждым кадром checkbox approval; не заменять молча.
- Для каждой утверждённой опции есть точная связь с конфигуратором (или ясно описанный fallback).
- Все galleries сохраняют model-scope и не показывают фото другого изделия.
- Редактор проверяет alt и подпись о визуализации там, где она нужна для честности.
- R8 проверяет 404, картинки размера 0, `alt`, mobile aspect-ratio/crop, загрузку через HTTP(S), sun/rain и невидимый дубликат.
- Производительность: зафиксировать реальные LCP, CLS и bytes by page; не ставить жёсткие безусловные размеры до измерения. Снижение веса без деградации восприятия.
- При `MISSING_ASSET` или `PENDING_APPROVAL` фаза 2/3 визуального builder получает `NO-GO`; первый UX/layout PR может быть принят независимо.
