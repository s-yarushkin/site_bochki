# Квиз R106 — редактура, дизайн и интеграция

31 октября 2026. Статус: работающий локальный предпросмотр на архитектуре R105. На домен квиз пока не установлен. Исходный ZIP DPQUIZ-a4c4ab3c1c6f изучен как материал для анализа; его установщик не запускался.

## Решение

Сохранён путь: приглашение → три вопроса → планировки и ориентиры цен → один запрос подборки → телефон и выбранный мессенджер. Результат и просмотр схем доступны до запроса контакта. Автоматически модальное окно не открывается. Не добавлены скидки, таймеры, подарки или неподтверждённые обещания.

Первый вопрос: «С кем будете отдыхать в бане?». Следующие — отдельная помывочная и спальня. Удалены «Тесновато, зато весело», навязанная экономия и избыточные бытовые описания. Нейтральные подписи рассказывают, как человек будет пользоваться баней. Микротекст «Вспомните обычный выходной на даче» помогает отвечать про привычный сценарий, а не разовый максимум гостей.

Приглашение: «Какая баня подойдёт вам? Ответьте на три вопроса. Сравните планировки и цены». Кнопка: «Найти свою баню». После результатов: «Сохраните планировки и комплектации с ценами» → «Получить подборку». Форма: «Куда отправить подборку?». Результат отправки обещает связь менеджера, а не автоматическую доставку документов.

Это проверяемые гипотезы для повышения числа квалифицированных заявок. Преимущество формулировок в конверсии пока не измерено.

## Дизайн

Manrope, лесной зелёный, тёплый светлый фон и радиус 3–4 px продолжают опубликованный сайт. Размеры заголовков и фотографий согласованы с нынешней страницей. Фасады взяты из её единого набора R101 вместо старой разнородной подборки.

Вопросы остаются короткими; одна карточка — одна кликабельная область. На компьютере — фотопанель и вопрос; на телефоне приоритет у ответов. Результаты — две колонки на компьютере, одна на мобильном. Добавлено увеличение схемы с прокруткой. Учтён prefers-reduced-motion.

## Исправления логики

- Исправлена точка подключения: у R105 `.section-heading`, а исходный квиз искал только `.section-top`, из-за чего launcher мог отсутствовать.
- Добавлено статическое место квиза с рабочей ссылкой на сравнение при недоступном JavaScript. Убрана дублирующая приглашение строка помощи в каталоге.
- Квиз использует тот же экземпляр `analytics-core.mjs`, что и R105. Старый импорт через runtime с другим query создавал отдельный экземпляр. В реестре сохранено ранее потерянное событие `dp_faq_open`.
- При восстановленном выборе модели автоматическая подсказка не показывается. Также учитываются действия с нынешними кнопками, формой и размерами. Повторная подсказка при сохранённых ответах подавлена.
- Для небольшой компании стандартные компактные корпуса показываются раньше крупных House. Спальня и помывочная по-прежнему фильтруют варианты, для большой компании сохранён приоритет просторных моделей. Например, для семьи со сравнением помывочной первым стал Парус 5 м вместо House 4×5. Это ранжирование, не изменение стоимости.
- Просмотр схемы передаётся менеджеру как «просмотрена», а не как якобы выбранная клиентом.
- Мобильная форма не открывает клавиатуру автоматически. Высота диалога учитывает visualViewport; область остаётся прокручиваемой.

## Цены и данные

Файл `web/data/quiz-v1.json`, 20 цен «Комфорт», доплаты и формула сохранены. Расчёт проверен по существующему снимку Google Sheets; свежий живой лист в этой редакции не перепроверялся. Внешний вид суммы с символом ≈ округлён вверх до целого рубля, внутренний расчёт хранит точные копейки. Цена договора не меняется.

Исходный каталог содержит 41 вариант и 39 старых изображений R93. Альбом в это время перерабатывается отдельно. Перед публикацией квиза необходимо сопоставить его активные варианты и изображения с окончательно проверенным альбомом, исключить снятый вариант и отделить дополнительные планировки. Непроверенные схемы не следует выдавать за новые. В предпросмотре пока сохранены исходные изображения для проверки UI.

## Проверка

- 20 тестов аналитики, квиза, каналов и цен (включая 24 сочетания ответов и новую проверку порядка показа).
- 5 тестов API: прежние контракты, выбранные мессенджеры, реальное локальное HTTP-сохранение, подтверждение и дедупликация через заглушку доставки.
- Полная Node-проверка вместе с прежними сценариями сайта: 26 тестов, все прошли. Статическая проверка исходной базы web также успешна. Тест старого Linux-установщика V1 в Windows не выполняется из-за отсутствия fcntl; его корректность для нового R106 не заявляется.
- Браузер: вопросы → результаты → просмотр/зеркало/увеличение → форма → успешная локальная заявка. В рабочую Метрику и менеджерам ничего не отправлялось.
- При ширинах 390 и 320 px горизонтального переполнения нет. Кнопки мессенджеров 54 px, отправка 52 px. Проверен уменьшенный viewport 390×430 и доступность отправки при прокрутке. Это проверка размеров браузерного фрейма; физическая клавиатура iOS/Android не тестировалась.

## Сборка и выпуск

`python r106/build.py` воспроизводит текущую архитектуру из исходников и подключает обновлённый квиз. Результат: `output/r106-site`, только предпросмотр. Для разработки: `DP_WEB_ROOT=output/r106-site`, `DP_TEST_PORT=4192`, затем `node scripts/dev-server.mjs`; все заявки локальные.

Исторический `web/index.html` не является опубликованной R105-страницей. Не заменять им корень сайта. Старый handoff проверяет якорь CSS R100 и хеши старых зависимостей; он не является установщиком этого R106-предпросмотра. Перед выпуском нужен отдельный проверенный пакет для текущего WEB/API, затем проверка приёма заявок на домене. API-поддержка quiz_catalog уже есть в репозитории; наличие её в действующем сервере пока не подтверждалось.
