# «Гарант Бани» V5 — исполняемая дорожная карта, узкие задачи и acceptance

**Версия:** 10.10.2026. **Статус:** план, не выполнение.  
**Главное ТЗ:** docs/GARANT-BANI-V5-MASTER-SPEC-2026-10-10.md  
**Реестр фото:** docs/GARANT-BANI-V5-MEDIA-REGISTER.md  
**Предполагаемая кодовая база:** рабочий функционал PR #6, уже выпущенный как 20261010-11ee8ba87261-two-managers. Ветка main может ещё не содержать его — перед первым PR по реализации сверить историю и базу.

## Правила доставки

- Каждая задача получает один code PR, или группу из 2–3 неразделимых задач; не устраивать «полную перепись сайта» одним непроверяемым PR.
- Каждый PR: ветка от актуального кода, описание changed files, фото до/после для SUN/RAIN (1440 и 390, хотя бы), результат тестов, известные ограничения, rollback. Публикация только из exact SHA после approval.
- Не перекраивать backend, менеджерскую авторизацию, цену и маршруты сервера параллельно с визуальными задачами. Изменение только front/theme/media — минимальный риск.
- Действующий сайт, Caddy, MAX, SQLite и чужие сервисы не обновлять без отдельной операции и preflight.
- Для задач с фото обязательны источник, право на использование, соответствие модели. «Не нашли фото» — blocker/placeholder, а не сигнал к генеративной выдумке.
- Статусы задач: TODO → IN_PROGRESS → PR_OPEN → QA_PASS → DEPLOYED → OWNER_ACCEPTED. PR_OPEN не значит DONE.

## Wave 0. Базовая линия и инвентаризация (PR V5-00, docs-only; блокирует все визуальные PR)

**V5-001 — Снять baseline production.**  
Вход: реально выпущенный SHA 11ee8ba…, снимки 1440/390/320 SUN и RAIN, маршруты и доступность.  
Действие: сохранить исходный вид hero/футера/каталога/конструктора/форм; проверить отсутствие JS errors и существующие CTA.  
Критерий: есть датированные screenshots обеих тем и проверенные URL; ни один продовый конфиг не изменён.

**V5-002 — Зафиксировать контракт безопасности и форм.**  
Вход: tests, менеджер API, рабочий callback.  
Действие: regression plan для callback и quote, MAX/SQLite, manager 2 logins, отсутствие утечек и неизменность цены.  
Критерий: до вмешательства в дизайн известен текущий PASS/FAIL каждого маршрута; callback подтверждён пользователем, quote помечен «needs live acceptance».

**V5-003 — Зафиксировать карту страниц и фото-слотов.**  
Действие: описать нынешние секции index.html, slotId в CSS/JS и соответствующие CTA; сопоставить с V5 media register.  
Критерий: нет «безымянных» слотов; каждый визуальный блок имеет source slot или approved placeholder.

**V5-004 — Снять измеримые параметры скорости.**  
Действие: baseline LCP/CLS/INP где измеряемо, Lighthouse mobile/desktop на одинаковом профиле, полный вес изображений и JS.  
Критерий: измерение документировано с тестовым устройством/сетью; непроверенные цифры не представляются как факты.

**Gate G0:** baseline и безопасный rollback зафиксированы, точная кодовая база для будущего PR определена. Никакой новой картинки пока не публиковать.

## Wave 1. Реальные фото Tilda / VK (PR V5-01 media inventory и PR V5-02 approved media)

**V5-005 — Уточнить официальный источник.**  
Проверить https://garant-bany.ru/ и ссылку на официальный VK из клиентских материалов; убедиться, что сайт действительно принадлежит клиенту.  
Критерий: verified URLs, даты проверки, связь с владельцем; нельзя подменять одноимённым сайтом.

**V5-006 — Получить разрешение на использование фотографий.**  
Действие: согласовать с собственником право публиковать и обрабатывать конкретные фото, включая сторонние/авторские права.  
Критерий: отметка RIGHTS_APPROVED и основание у каждой публикуемой единицы; до этого скрины могут использоваться только во внутреннем review при наличии разрешения.

**V5-007 — Составить raw-список ассетов.**  
Собрать URL файлов и страниц из Tilda/VK, сохранить размеры, ориентацию, исходные имена, где размещены, возможные дубли.  
Критерий: реестр с sourcePage и candidateSlot, без безымянных «photo1». Исходные бинарные файлы не коммитить без approval.

**V5-008 — Проверить товарную идентичность.**  
Для каждой фотографии определить Квадро/Парус/Викинг/Квадро Хаус или UNKNOWN с согласованием владельца.  
Критерий: UNKNOWN никогда не становится обложкой модели без подтверждения.

**V5-009 — Выбрать hero SUN/RAIN.**  
Выбрать дневной кадр и документальную пасмурную/вечернюю пару того же изделия, если существует.  
Критерий: внешняя геометрия узнаваемо та же; если пары нет, одобрена fallback-политика «один реальный кадр + два цветовых UI-контекста», без ложной подписи о другом времени суток.

**V5-010 — Выбрать каталог.**  
Для каждого из четырёх семейств выбрать один проверенный фасад/ракурс 3/4.  
Критерий: четыре точные привязки или честные placeholders; никак не «одно фото на все модели».

**V5-011 — Выбрать другие доказательные фото.**  
Отдельно: интерьер/парная/полок/печь/бак (4–6), готовые бани на участках (3–4), доставка/монтаж (2–3), фото комплекта/CTA (2–3).  
Критерий: отсутствующие категории явно обозначены TODO; отсутствие не заполняется сторонними стоками под видом объектов.

**V5-012 — Обработка и экспорт.**  
Лёгкие правки экспозиции, баланса белого, горизонта, кадрирования, шума; первичное изображение и derivative не путаются.  
Критерий: нет изменения конструкции или комплекта; есть источник + hash. Подготовлены desktop/mobile варианты и форматы WebP/AVIF, разумный размер/вес.

**V5-013 — Media manifest и rendering fallback.**  
Добавить source-controlled manifest slotId → modelId/source/type/variants/alt; renderer уважает отсутствие ассета и placeholder.  
Критерий: один слот не выдаёт фото другой модели, 404/failed image не рушит layout.

**V5-014 — Owner photo acceptance.**  
Владелец бизнеса утверждает каждую подмену; «на фото именно наша баня, модель и комплектация соответствуют заявленным».  
Критерий: approved media manifest/реестр; реальные фотографии можно публиковать только после этого.

**Gate G1:** права, идентичность, источники и placeholders проверены. Хороший кадр без прав/идентификации не считается подходящим.

## Wave 2. Две полноценные темы и переключатель (PR V5-03 theme foundation; V5-04 toggle+media)

Критерий: 10 последовательных переключений не меняют выбранные опции, цену, заполненную форму и состояние конструктора.

**V5-018 — Спроектировать toggle вне фото.**

Критерий: нет визуального перекрытия объекта на 320/390/768/1440; кликабельная зона >=44 px; keyboard и aria-pressed.

**V5-019 — SUN/RAIN hero asset swap.**

**V5-020 — Тематизировать интерфейсные состояния.**  
Полный проход по: card, CTA, inputs, disabled/error/success, consent, dialog, accordion, price, tooltip.  
Критерий: theme screenshot matrix на обоих режимах; цвет не единственный индикатор.

**V5-021 — Motion/keyboard/memory discipline.**

Критерий: нет скачков layout, focus trap, animation-only действия; выбранный weather не уходит в storage без нового решения.

**Gate G2:** темы глобальные, toggle органичен, обе темы одинаково функциональны. Тёмная тема не должна быть «тот же светлый сайт с тёмным hero».

## Definition of ready для каждой узкой задачи

- Ясный визуальный/пользовательский дефект и ожидаемый результат.
- Список файлов, затрагиваемых изменений и тех, которые трогать нельзя.
- Утверждённый источник изображений/фактов или явный placeholder.
- PASS/FAIL критерии и воспроизводимый тест.
- Возможность отменить изменение без потери персональных данных.
- Отдельный коммит/PR/owner gate.
