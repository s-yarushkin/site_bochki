Лист `Рабочий калькулятор`, колонка `C`, заголовок `ЦЕНА НА САЙТЕ, ₽`.

Связи с Google в runtime сайта до этого не было. Этот релиз устанавливает **проверенный снимок**, а не автоматическую синхронизацию. Дальнейшие изменения таблицы сами на сайт не попадут. Для следующего обновления нужно заново прочитать колонку, сформировать снимок, проверить и установить согласованно с backend. Не публикуем всю таблицу ради CSV: там есть внутренние РРЦ и дилерские данные.

`data/source/site-prices-2026-10-16.json` хранит только названия, номера строк и цены сайта. Ни дилерские цены, ни РРЦ, ни скидки/галочки рабочего калькулятора туда не копируются. `priceSource` содержит точное соответствие каждой модели/размера и каждого из 15 существующих дополнений ячейке C. Импортёр отклоняет пропущенные, нулевые, дробные цены и неоднозначные строки; подстановок из соседних колонок нет.

## Совместимость и установка

Версия нового прайса: `2026-10-16-sheet-site-v1`. Frontend передаёт её в configuration.pricebookVersion. Backend выбирает только известный серверный прайс, пересчитывает сумму сам, игнорирует присланные суммы. Неизвестная версия отклоняется.

Клиенты V6.6/V7.2 без версии сохраняют исторический прайс `2026-10-12-v66-owner-review-3`; V6.4 без consentVersion сохраняет отдельную ранее принятую историю. Старый домен продолжает работать на старом frontend. Оба consentVersion, Origin, Host, CSRF, cookie Path, сессии, транспорт MAX и схема SQLite сохранены.

`ops/price-release.ps1 -SourceSha <точный SHA>` проверяет Node и браузер локально, доставляет архив с per-file manifest, запускает `ops/price-release-install.py`, затем повторяет браузерную проверку по HTTPS. Установщик принимает точный подтверждённый backend 56bf8a1a82d2 и frontend после SEO-релиза 286ab17b3a02 либо телефонного hotfix 2226029e175e. Он проверяет известные LF/CRLF варианты файлов, Caddy validate, systemd, health и 401 для обоих доменов.

Копирует релизы, делает согласованную read-only SQLite backup в закрытый каталог, проверяет новые и исторические суммы импортом staged runtime без открытия рабочей базы/без MAX. Сначала активирует совместимый backend, затем новый frontend. Меняется только существующий сервис garant-bani-relay; Caddy/env/systemd-настройки и соседние проекты не меняются. После активации сверяет HTTPS-байты страниц и JSON, noindex служебных страниц, 401 кабинета и старый сайт.

При ошибке после начала активации автоматически возвращает оба symlink и перезапускает прежний backend. Откат отказывается перезаписывать конкурирующий релиз. База заявок при откате **не восстанавливается из backup и не удаляется**, поэтому новые реальные заявки не теряются. Команда ручного rollback печатается установщиком и сохраняется рядом со state.json.
