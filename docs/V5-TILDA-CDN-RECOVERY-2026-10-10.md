# V5 — восстановление доступа к изображениям после Node fetch failed (10.10.2026)

## Подтверждённый факт

Пользователь запустил `npm run check` на PR #10 до текущего исправления: **80 тестов PASS**, включая тесты экспортёра. Однако на реальной Windows-машине `node ops/export-tilda-photo-review.mjs` выдал `fetch failed` на **всех 36** CDN оригиналах; `REVIEW_SAVED=0`, архив не создавался. Часть Tilda HTML страниц при этом загружалась в предыдущем шаге (5/5).

**Это не доказывает конкретную причину сети.** Возможны отсутствие DNS на `static.tildacdn.com`, проблема TLS/доверенного CA, прокси или сетевой доступности. В клиентском скрипте раньше сохранялось только `error.message`, без `error.cause`. Исправлено для последующих экспортов.

## Вариант восстановления (без повторного сбора 102 ссылок)

Создан `ops/recover-tilda-photo-review.ps1`, предназначенный для **Windows PowerShell 5.1**, который берёт существующий `$env:TEMP\GB-V5-photo-review-a5a05d92\review.json`.

- Отправляет запрос к `static.tildacdn.com` через Windows `Invoke-WebRequest` (TLS 1.2, обычные системные proxy/cert), при неуспехе — через установленный `curl.exe`.
- Скачивает только оригиналы `https://static.tildacdn.com` в `photos/GBV5-…`; не принимает внешний хост, нестандартное имя или переход на сторонние домены.
- Проверяет первые байты реального PNG/JPEG/WebP/GIF/AVIF и максимум 16 MiB, вычисляет SHA-256.
- Обновляет существующий локальный `review.json` и офлайн контакт-лист `index.html`, формирует `GB-V5-photo-review.zip` с фото и диагностикой.
- Если подряд **три** URL не удалось скачать, а успешных скачиваний нет, прекращает попытки, но сохраняет `network-diagnostics.txt` и ZIP, не повторяя все 36 сетевых ошибок.
- Не публикует фотографии и не изменяет production. Права/model идентичность остаются UNVERIFIED.

Транспортный PowerShell-фолбэк ещё не подтверждён фактическим запуском пользователя. **Не заявлять о его PASS без вывода.**

### Следующий вызов

После fetch ветки PR #10 запустить `powershell -NoProfile -ExecutionPolicy Bypass -File ops/recover-tilda-photo-review.ps1` из корня checkout. Вывод всегда явно сообщает `PHOTOS_SAVED`/ `PHOTOS_PENDING`; если фото недоступны — `CDN_TRANSPORT_BLOCKED=YES`, `PHOTO_NETWORK_DIAGNOSTICS=REQUIRED`. В обоих случаях ZIP содержит результаты/ошибки, поэтому его можно передать для дальнейшего решения.

Если оба транспортных механизма не работают, сперва установить истинную причину по диагностике (не отключать TLS-проверку), затем искать легитимный доступ к оригиналам через собственника/второй одобренный канал. Не предлагать обходные CDN-прокси без проверки прав и безопасности.
