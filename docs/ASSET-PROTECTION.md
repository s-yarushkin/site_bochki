## Сборка и проверка

1. `python scripts/fetch-asset-baseline.py` получает только публичный снимок
   действующего web, фиксируя все SHA256 и отдельный API target.
2. `node scripts/asset-review-server.mjs` открывает локальное сравнение на
   `http://127.0.0.1:4205/__review3d`. Кнопка сохраняет 22 превью и проверяет движения.
3. `node scripts/build-watermarked-assets.mjs` строит защищённые файлы в
   `.local/asset-refresh/overlay/web`. Нужны Sharp (проверено 0.35.5) и Node 24;
   на этом ПК используется bundled runtime. Векторная подпись — Arial/DejaVu Sans.
4. `node scripts/verify-watermarked-assets.mjs` декодирует все растры,
   проверяет размеры, маркеры, alpha и неизменность исходных SVG-объектов.
5. `node --test tests/asset-watermarks.test.mjs` проверяет материалы, прозрачность,
   идемпотентность, размеры и сохранение geometry/texture/motion references.
6. `--stage-source` у сборщика копирует производные в явно записанные source paths;
   originals из снимка не перезаписываются. `prepare-asset-deploy.py` создаёт
   sealed package: 574 файла изображений и 6 файлов просмотрщика/стилей.

## Публикация и откат

На сервер загружаются payload, deployment.json и `deploy-assets-remote.py`.
Сначала `--check` под deploy проверяет копию релиза и все защищённые SHA256.
Затем `publish-assets-terminal.py` принимает sudo скрытым вводом и вызывает `--apply`.
Пароль остаётся в RAM окна. Новый web собирается рядом с прежним и включается
атомарным symlink. API не перезапускается; база, credentials, MAX и Caddy не меняются.
После переключения сверяются опубликованные файлы и защищённые страницы, health
и весь API release. Ошибка возвращает прежний web автоматически.

Для отката: `sudo python3 /tmp/dachapar-assets-<commit>/deploy-assets-remote.py --rollback`.
Точный путь и предыдущий релиз записываются в результат и root-only backup state.
Откат допустим только пока этот новый релиз активен и не было другого обновления.
Перед новыми изображениями запускайте тот же сборщик и проверку покрытия.
