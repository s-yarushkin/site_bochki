## 2. Условия перед переключением (GO)

1. Продолжает работать именно R8.0 и зафиксированный API. Если `current`, релизы или SHA изменились — **ABORT**, не форсировать.
2. На Windows существует исходный JSON-отчёт 42 QA и подтверждает **41 PASS, 0 FAIL, QA08 NOT_TESTED**, корректное имя stage и **0 production writes**. QA08 принято только как исключение к публикации без статистического утверждения.
3. Менеджер подтверждает операционную готовность бесплатно готовить и отправлять **индивидуальную комплектацию, планировку, чертёж и расчёт** по запросу: кто принимает заявки, где видит пожелания и кто отправляет материалы. Нет автоматической генерации и отправки.
4. Зафиксированы действующий телефон, доступ менеджера и резервный способ связи; проверено, что резервный R8.0 хранится на сервере. Данные SQLite не требуют миграций: API и БД не трогаем.
5. Подтверждено отсутствие неподкреплённой фразы `80% клиентов...` в новом релизе. Архив FIX2 проверен отдельно: 64 файла, этой фразы нет.
6. В отдельном окне PowerShell доступен оператор с SSH и `sudo`; команда `-Rollback` сохранена заранее.

**Если любое из условий 1–5 отсутствует — пока не активировать.**

## 3. Получение и запуск защитного комплекта

Сохранить в `Downloads` комплект `DachaPar_R81_Cutover_Kit_20261023.zip` и имеющийся `DachaPar_R81_CJM_FIX2_20261023.zip`. Распаковать отдельно:

```powershell
$kit = "$env:USERPROFILE\Downloads\DachaPar_R81_Cutover_Kit"
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\DachaPar_R81_Cutover_Kit_20261023.zip" -DestinationPath $kit -Force
```

В комплекте: `DachaPar_R81_Cutover_Guarded_20261023.ps1`, `r81_release_guard.py`, этот регламент. **Сохранять PS1 и PY в одной папке.** Не использовать скрипт от R8.0 или серверную stage-команду для активации.

### Шаг A. Предварительная проверка (по умолчанию, без переключения)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File (Join-Path $kit 'DachaPar_R81_Cutover_Guarded_20261023.ps1')
```

Скрипт проверяет локальные SHA, JSON-отчёт 42 QA, точный текущий `current`, API, аудит stage, 64 файлов, неизменность защищённых файлов и отсутствие маркетингового утверждения. Вызывает существующий `installer.py` **без** `--activate` (read-only preflight). Временная копия инструментов на сервере находится **только в `/tmp`** и удаляется после выполнения.

Ожидаемый признак: **`R81_WINDOWS_PREFLIGHT=PASS; WEB_STILL_R80=YES; PRODUCTION_WRITES=0`**. Вплоть до этого момента сайт не переключать. Любой `...DRIFT`, `MISMATCH` или `...FAILED` — остановка.

### Шаг B. Переключение (только после GO)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File (Join-Path $kit 'DachaPar_R81_Cutover_Guarded_20261023.ps1') `
  -Deploy `
  -ManagerReady `
  -Approval 'PUBLISH_R81_FIX2_WITHOUT_80_20261023'
```

`-ManagerReady` — **осознанное подтверждение** пункта 3 выше, а не технический тест. Выполнить только после получения PASS на шаге A. Действие необратимо в смысле появления нового сайта на публичном домене, но **веб-версия** может быть быстро возвращена на R8.0.

Скрипт повторно выполняет префлайт; затем вызывает **оригинальный** установщик FIX2 с `--activate <точный stage>`. В нём атомарная смена ссылки `/srv/sites/dachapar-preview/current`, сверка всех изменённых публичных файлов (только GET) и автоматический откат при ошибке. Дополнительная проверка повторно сверяет stage, источник, API и ключевые публичные файлы; её провал также приводит к откату через независимый guard.

Ожидаемый итог: **`R81_WINDOWS_CUTOVER=PASS; WEB=R81_FIX2; API_UNCHANGED=YES; SQLITE_UNTOUCHED=YES; MAX_POSTS=0`**.

### Шаг C. Контроль живого сайта

1. Открыть главную в приватном окне на компьютере и телефоне; проверить, что **«Оставьте неделю за дверью»**, четыре модели, калькулятор, реальные бани и смена сцен «камни / веник / отдых» показываются без ошибок.
2. Открыть `/bani/kvadro/#komplektatsii`: **Квадро 5 м Комфорт 505 000 ₽**, **Делюкс 618 022 ₽**; фразы «80%» нет. Из карточек перейти в калькулятор; версия Делюкс загружается с точным набором дополнений, после F5 сумма не сбрасывается.
3. Открыть `/bani/viking/`: шесть схем, индивидуальные широкие варианты не получают стандартный прайс. `/bani/parus/`: пять схем. `/bani/kvadro-haus/`: четыре схемы и цена со сборкой в итоговой сумме. `/raboty/`: 10 серий, один объект — одна фотогруппа.
4. Открыть форму запроса бесплатной планировки без выбора модели: «Помочь выбрать модель», никаких придуманных размеров и сумм. **Не отправлять пробную заявку в рабочий MAX**; имитация отправки уже проводилась в локальной QA.
5. Проверить `/#configure`, `/#packages`, `/journal/kvadro-5-komfort/` (контент уже про Делюкс), внутренние ссылки, документы `/privacy.html`, `/consent.html`, `/requisites.html`.
6. Войти в существующий `/manager.html` под разрешённой учётной записью и убедиться в работе входа и существующих заявок **без изменения или удаления данных**. Сервер/API/2FA не перерабатывались; проверить хотя бы открытие и чтение. Подтверждение реального получения новой заявки в MAX — отдельная авторизованная операционная проверка, не подмена синтетической QA.
7. Отдельно проверить мобильную липкую CTA и видимость формы/цен на узком экране. Зафиксировать скриншоты и время проверки.

### Шаг D. Наблюдение

При ошибках в цене, сломанной форме, массовых 404, неправильной галерее, недоступном кабинете или отсутствии критических ресурсов — **откатить WEB сразу**. Не удалять ни один релиз до завершения наблюдения. Следить за HTTP-ошибками и входящими обращениями; не изменять одновременно API, цены, правовые страницы или авторизацию.

## 4. Аварийный откат R8.1 → R8.0

**Откат отдельной командой, без ZIP R8.1, QA-отчёта и без GitHub Actions.**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File (Join-Path $kit 'DachaPar_R81_Cutover_Guarded_20261023.ps1') `
  -Rollback
```

Скрипт на сервере использует тот же файловый lock, что и штатный установщик; проверяет, что сейчас активен **ровно R8.1 FIX2**, предыдущий R8.0 существует и соответствует аудиту, затем атомарно возвращает symlink. Повторный вызов после успешного отката безопасен: `R81_MANUAL_ROLLBACK=ALREADY_R80`.

Ожидаемый итог: `R81_MANUAL_ROLLBACK=PASS; WEB=R80; PUBLIC_HASH=PASS` или, если откат уже выполнен штатным установщиком, `R81_MANUAL_ROLLBACK=ALREADY_R80`. После отката проверить главную, калькулятор, вход менеджера и отсутствие нового сбоя; API, данные SQLite и заявки сохраняются.

**Важно:** это откат только WEB. Если в интервале публикации появился реальный новый запрос, серверную БД не откатывать и заявки не удалять. Если SSH оборвётся во время публикации, **не повторять `-Deploy` вслепую**: сначала проверить статус:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File (Join-Path $kit 'DachaPar_R81_Cutover_Guarded_20261023.ps1') `
  -Status
```

Если статус уже R8.0 — повторная публикация только после разбора причины; если R8.1 FIX2 — проверить фактические страницы или запустить `-Rollback`.

- Штатный вывод `R81_DEPLOY=PASS` и `R81_WINDOWS_CUTOVER=PASS`.
- Проверка живого сайта из шагов C1–C7 без критических замечаний, работоспособность кабинета и входящего маршрута обращений подтверждена отдельно в операционном контуре.
- Прежняя версия доступна для немедленного WEB-отката.
- Записаны дата/время, старый и новый путь, результат проверки, известное исключение QA08 и ответственный за обработку бесплатных индивидуальных проектов.

**Исключение QA08 не считается PASS.** Статистическую фразу допустимо добавить только отдельным изменением после проверки оснований и новой приёмки. При текущем решении публикация *без* этой цифры не блокируется QA08.
