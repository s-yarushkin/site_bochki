## ROOT CAUSE: исчезающие стрелки нарушают CSS Grid auto-placement

Исходный `parus-media/widget.css`:

```css
.pp-gallery-stage {
  display: grid;
  grid-template-columns: 44px minmax(0,1fr) 44px;
}
/* У главного фото не было grid-column */
.pp-gallery-stage > img { width: 100%; height: min(53dvh,600px); object-fit:contain }
```

Исходный `widget.mjs`:

```js
for (const b of dialog.querySelectorAll('[data-pp-step]'))
  b.hidden = object.photos.length < 2;
```

У фотогруппы `timber` («Дерево и белое остекление») **один кадр**. Две стрелки становятся `hidden`; первая видимая дочерняя сущность Grid — **главное изображение**. Оно автоматически размещается в **первой колонке, предназначенной для стрелки**, шириной 44 px на компьютере или 36 px на мобильном экране. Из-за `object-fit:contain` реальная видимая фотография получается примерно **44×59 px** на desktop — как на скриншоте владельца.

Это доказанная причина с *оригинальным* виджетом, настоящими CSS и WebP, **без добавления искусственного** `img{width:44px!important}`. Ранее предполагаемый конфликт глобальных CSS был лишь гипотезой — новая проверка её заменяет.

## Фикс

В новом `parus-media/widget.css` главное изображение жёстко закреплено во второй колонке:

```css
.pp-dialog .pp-gallery-stage > img#pp-gallery-image {
  grid-column: 2 !important;
  grid-row: 1 !important;
  width: 100% !important;
  object-fit: contain !important;
}
```

`widget.mjs` дополнительно проверяет геометрию и обеспечивает fallback 1600→960 px. Миниатюры, стрелки, планировки и цены не меняются. В `content.mjs` никакие сведения об объектах не меняются: **4 группы, 10 опубликованных фотографий, 5 планировок**, без связи готового объекта с конкретной ценой или планом.
