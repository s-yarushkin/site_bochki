# Кабинет команды и собственные источники

Адрес кабинета: https://дачапар.рф/manager.html. После обновления потребуется
один раз войти заново. Старые пароли импортируются без изменения; новые
сотрудники меняют временный пароль при первом входе. Временные пароли выдаются
только в приватном окне установки или владельцу в разделе «Сотрудники».

## Права

- Владелец: заявки, сотрудники, роли, ссылки, источники, действия, посетители,
  журнал. Системная роль владельца неизменяема; последнего владельца отключить нельзя.
- Менеджер: все заявки, статусы, ответственный, заметки, история до своей открытой
  заявки, закрытие как тестовой с причиной. Восстанавливать тестовые может владелец.
  Сотрудники, роли, общий список посетителей и сводные отчёты закрыты сервером.
- Изменение роли, блокировка и сброс пароля завершают сеансы сотрудника.
  Новые роли выбираются из серверного списка разрешений.

## Ссылки и отчёты

В «Ссылки» создайте отдельную запись для каждой публикации/кампании/партнёра.
Укажите площадку, тип и внутренний адрес страницы, например
`/?bath=parus#bath-model`. Скопируйте короткую `/go/...` или полную UTM-ссылку.
Копия получает новый идентификатор; переименование/архив сохраняют прежний источник.
Архивная или приостановленная ссылка продолжает открывать страницу.
Безопасный редирект сохраняет допустимые yclid/gclid и параметры выбора модели.

«Источники и продажи» показывает отдельно технические переходы, подозрительные
боты, визиты и уникальные браузеры с согласием, реальные заявки, доставку в MAX,
продажи со статусом «Продано». Даты — Москва; сравнение с предыдущим равным
периодом, таблица по дням, first / last non-direct / conversion и окно 7/30/90.
Нажмите количество заявок в строке, затем номер для открытия карточки.
Уникальные за период считаются как множество браузеров, а не сумма по дням.
Выручку из предварительной цены бани не рассчитываем.

«Действия» — охват событий, кнопок, моделей и планировок, а не обязательная
последовательная воронка. «Посетители» — последние 100 разрешённых браузеров,
внутри до 100 визитов / 1000 событий. Карточка заявки показывает историю только
до заявки и её серверное подтверждение. Между устройствами склейки нет.

## Согласие и точность

До выбора «Согласен на все cookies» нет собственной истории и Яндекс Метрики.
«Только необходимые» оставляет сайт и формы работающими. Подписанная метка
специальной ссылки связывает публикацию с заявкой даже без visitor cookie.
Без согласия нельзя выводить число уникальных посетителей или историю выбора.
Отзыв через «Настройки cookies» удаляет историю текущего браузера; заявку сохраняем.
Срок истории 180 дней, серверная очистка при запуске и каждый час.

Без referrer/меток источник остаётся прямым/неизвестным. Старые данные не
восстанавливаются. Известные служебные браузеры исключены из новых событий и
коротких переходов cookie `dp_staff=1` на 8 часов после входа в кабинет.
Вход из другого браузера этим исключением не покрывается. Метрика работает
отдельно: OAuth, импорт её отчётов и проверка зарегистрированных целей в этот
релиз не входят по решению владельца. Вебвизор не включаем.

## Проверки и откат

Локальные тесты: `node --test tests/crm-access.test.mjs tests/crm-insights.test.mjs
tests/crm-bootstrap.test.mjs tests/crm-stage.test.mjs tests/api.test.mjs tests/analytics.test.mjs`.
Для API-тестов нужен точный исходный API в `.local/api-baseline`, без credentials.
Сборка: `scripts/crm-build-package.py`; явный manifest 22 web/API файла.
HTTPS staging — отдельная вымышленная БД и заглушка MAX, отдельные cookies
и временный URL. Проверка production не отправляет реальных заявок.

Публикация: `crm-publish-terminal.py` принимает sudo через скрытый ввод,
поднимает stage и ждёт файла `stage-accepted.json` с тем же ID. После проверки
делает свежий согласованный SQLite backup + isolated restore, проверяет
аудированные исходники API, копирует релизы и сверяет все защищённые файлы.
Миграция только явная: штатный запуск сервера не создаёт пользователей/права.
Секреты MAX, старые хэши и session secret остаются на сервере.

Флаги в `/etc/systemd/system/garant-bani-relay.service.d/90-crm.conf`:
`CRM_ENABLED=1`, `CRM_TRACKING_ENABLED=1`. Трекинг можно выключить отдельно,
оставив кабинет, источники заявок и формы. Для полного отката вернуть прежние
web/API symlink и прежний drop-in, daemon-reload/restart API, затем прежнее
правило Caddy и validate/reload. Добавленные таблицы совместимы со старым API.
**Нельзя накатывать старый снимок БД поверх новых заявок.** При неудаче
публикации автоматический откат кода/конфигурации не откатывает БД.
