## Выявленные риски содержания

- Существующий Tilda-сайт публично использует цены, маркетинговые сроки, тезисы о прогреве и долговечности. Это **не утверждённые данные для V5**. Не копировать ни розничные цифры с Tilda, ни дилерские значения во фронтенд V5.
- Страница «Викинг» в доступной текстовой версии содержит карточку `КВАДРО 400` среди модификаций Викинга — возможная ошибка старой Tilda-разметки. Поэтому нельзя определять принадлежность каждого фото только из URL страницы. Проверить по фактическому изделию и у собственника.
- Главная Tilda упоминает сборку модулей на фундаменте, поэтому универсальный лозунг «привезли полностью готовую баню без какой-либо сборки» может быть неточным для части ассортимента. Выносить в копирайт только согласованную модель доставки.
- Реальной парной фотографии «того же объекта» в SUN/RAIN парах пока **не установлено**. До подтверждения использовать честную дневную фотографию в обеих темах, меняя только окружение UI, либо placeholder.
- Не приписывать фотографиям географическую точку, дату установки или комплектность без первичных данных.

## Как воспроизводимо собрать кандидатов

Из корня **рабочей кодовой ветки сайта** с Node 24+:

```powershell
node ops/collect-tilda-media.mjs
```

Отчёт сохраняется только на локальном устройстве по пути, который напечатает `TILDA_AUDIT_FILE` (обычно системная TEMP-папка). Для указания своего пути:

```powershell
node ops/collect-tilda-media.mjs --out "$env:TEMP/garant-bani-tilda-audit.json"
```

Полезные поля в отчёте: sourcePage, sourcePageId, sourceUrl, count, errors, rights=UNVERIFIED, model=UNVERIFIED, publishable=false. Поля права и идентичности **намеренно закрыты**: даже если URL публичен, дизайнер не должен автоматически помечать фотографию как согласованную.

### После сбора

1. Устранить недоступные страницы/неудачный парсинг только по фактическим логам; не подставлять изображения похожего производителя.
2. Построить контакт-лист кандидатов и установить: оригинальный размер, резкость, категория изображения, дубли.
3. Получить от клиента согласование прав и принадлежности конкретного кадра серии и варианту.
4. Составить JSON media manifest по `slotId` (единый вид в обеих темах, если нет честной SUN/RAIN пары).
5. Оптимизировать реальные файлы в локальные WebP/AVIF, проверить weight, crop и UX.
6. Внести готовые файлы отдельным фото-PR и проверить визуально все четыре модели.

**Этот PR не скачивает, не перекрашивает и не публикует изображения.** Это отдельный этап G0/G1, подготавливающий достоверное наполнение следующего медиа-PR.
