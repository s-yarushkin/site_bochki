# ДачаПар · R8.3.2 — редактура сайта, новый «Комфорт» и конверсия
Редакция: 24 октября 2026. Статус: **код подготовлен в PR #96; stage и production не подтверждены**.

## Согласованное продуктовое решение
- **Ни одной новой цены.** Сохранить все 20 текущих цен сайта, скидки, формулы, актуальные цены «Комфорт» и «Делюкс», ответы калькулятора и старые коммерческие ссылки. Google Sheets 2026-10-24 — рабочая модель для отдельной задачи и не источник обновления клиентского прайса в этом релизе.
- «Комфорт» — **готовая баня, в которой уже учтено всё необходимое для парения**, а не пустая базовая конфигурация с обязательными доплатами.
- В стандарт входят печь/дымоход/бак, полки, ПВХ-дверь 700×1800, окно ПВХ 600×800, форточка в парной, два светильника с абажурами в парной, свет в других помещениях, два комплекта розеток, выключатели, штатная электрика, стол, лавки, шкаф, вешалки. В подробной технической спецификации — вентиляция, слив, устройство пола, электробезопасность и особенности модели.
- Пятёрка **необязательных** улучшений: LED-подсветка парной, наружное освещение, откидной стол, лавки-рундуки, вынос топки в смежное помещение либо наружу **если конструкция позволяет**.
- Два CTA на всех страницах моделей: **«Рассчитать баню с улучшениями»** → `/#configure`; **«Получить консультацию и планировку бесплатно»** → `/#relay-lead-form`. Это существующие якоря; новые маршруты передачи заявок не создаются. Пояснение: менеджер расскажет о составе, подберёт варианты планировки и проконсультирует о доставке. Заказывать баню необязательно.
- Нет галочек «Уже включено». Правила доплат за замену дверей/окон и новый расчёт себестоимости — **отдельный следующий этап**. Не начислять включённые позиции второй раз.

## Содержание существующего редакционного патча
43 группы аудита: убрать ложные или обесценивающие счётчики бань, служебные подписи, перепутанные «База/Комфорт/Делюкс», технический язык в продающих блоках и воронке, объяснить галереи/планировки, переписать FAQ, 13 статей, доставку, контакты и форму.
- 4 модели: полноценный продающий блок «Комфорт», примеры опций, 2 CTA, подробная спецификация в раскрываемом `details`.
- 4 карточки главной + 4 карточки каталога: короткий человеческий тезис.
- FAQ и статья о комплектациях синхронизированы с новым составом; старые примеры деревянных дверей/окон **не выдаются за сегодняшний продаваемый «Комфорт»**.
- Фото, источники галерей, SVG, цены и критические файлы не переписываются.

## Важный коммерческий риск — перед публикацией
В действующем `data/catalog-pricebook.json` у демонстрационного «Делюкс» (Квадро 5 м) уже встречаются платные позиции форточки 3 510 ₽ и шкафа 9 360 ₽. Теперь обе должны входить в «Комфорт». **12 870 ₽ потенциального пересечения**. Это не повод менять опубликованные цены 505 000 ₽ / 618 022 ₽; нельзя незаметно уменьшать прибыль или суммировать включённое повторно.

Для выпуска в production нужен отдельный контроль клиентского расчёта «Делюкс» и доступных допов: не обещаем двойную продажу и не называем все 113 022 ₽ «платой за 12 дополнительных товаров» без сверки SKU. Если новая копирайтинговая версия вступает в конфликт с реальным механизмом quote, **деплой блокируется**. Продающий текст сам по себе проблему калькулятора не устраняет.

## Защитные границы
Трансформация использует фактическую WEB-базу `VIKING-BUILT-20261024-1792838766529643617`. При другом активном WEB stage/activation прерывается. API ожидается `R73-LEGAL-db5d49445661-1792566478879449075`. Не трогать личный кабинет, TOTP, MAX, SQLite, сервис API, `quote.mjs`, `data/catalog-pricebook.json`, ПДн, юридические страницы, старые URL, фото, SVG.

Все 43 группы аудируются CHANGED/ALREADY/NOT_FOUND. Блокируются неожиданные изменения файлов, несоответствие SHA, отсутствие двух CTA, неверная цена 505 000 ₽, неверная сумма «Делюкс» 618 022 ₽, нарушение существующей формы `relay-lead-form`.

## Исполнение (отдельные шаги)
1. На Windows запустить bootstrap из R8.3.2 kit, скачивающий **закреплённую ревизию** четырёх исходных файлов GitHub с проверкой Git blob SHA-1. Он создаёт `r83_payload.zip` с редактором и защищённым installer и PS-обёртку с SHA256 запакованного payload и браузерной проверки. Никакого GitHub Actions или Desktop Commander.
2. `DachaPar_R83_Copy_Comfort.ps1 -Stage`: создаёт отдельно изолированный WEB stage, без изменения public.
3. `DachaPar_R83_Copy_Comfort.ps1 -QA -StagePath <точный путь stage>`: читает точные HTML с stage, проверяет hash и Chromium/Edge на 390/768/1366/1920; отправка POST запрещена.
4. Прочитать редакционный аудит; проверить вручную коммерческую коллизию «Делюкс» и реальный расчёт со включёнными позициями; проверить модель/якоря CTA, фото и мобильный экран.
5. **Только после явного допуска**: `DachaPar_R83_Copy_Comfort.ps1 -Deploy -StagePath <точный путь stage> -Approval R832_COPY_COMFORT_APPROVED`. Production переключается атомарно с автоматическим rollback при несовпадении публичных SHA.
6. При необходимости `-Status` или `-Rollback`. Критичные API/SQLite/MAX/manager не меняются ни на одном этапе.
