# Исправление общей формы заявки, 05.11.2026

Опубликовано на основном домене. Активный выпуск:
`/srv/sites/dachapar-preview/releases/BC-45bb11dcf8b51b79`.

## Причина

Плавающая кнопка справа внизу, финальная кнопка и приглашение к обсуждению
открывают одну форму `inquiry-dialog`. По умолчанию в ней выбран способ связи
«Позвонить». Код ошибочно добавлял `purpose=quiz_catalog` при любом способе связи.
Сервер разрешает этот тип только для MAX, Telegram и WhatsApp, поэтому отклонял
телефонный вариант с `INVALID_QUIZ_REQUEST` до сохранения заявки и доставки.

Сбой воспроизведён на исходном коде опубликованного выпуска и изолированном
валидаторе. Предыдущая проверка отправки охватывала каталог и квиз и пропустила
нижнюю форму с телефонным вариантом. Один тест текста и контекста формы этого
не выявил.

## Исправление и проверки

Для «Позвонить» используется штатный callback без специального purpose.
Для мессенджеров сохранён существующий контракт. Серверные проверки не ослаблены.
Версии трёх загружаемых модулей обновлены, чтобы после перезагрузки страницы
браузер получил исправленный код. Публично изменились только четыре файла:
`index.html`, `choice/app.mjs`, `choice/continuation.mjs`, `choice/continuation-state.mjs`.

- PASS: 13 тестов API, общей формы, её контекста и каналов связи.
- Новый тест проводит все четыре канала через настоящий HTTP-обработчик,
  SQLite в памяти и заглушку доставки; проверяет `ok`, `delivered`,
  `analytics.persisted`, сохранённые выбор и пожелания.
- PASS: четыре отправки нижней формы в браузере на локальный изолированный
  обработчик. У всех показано подтверждение.
- PASS: отдельно отправка после нажатия именно плавающей кнопки справа внизу.
- PASS: контрольные суммы четырёх исправленных файлов на основном HTTPS.
  Установщик дополнительно проверил все 124 файла публикации.
- PASS: новый скрипт загружается с `?v=phone-callback-20261105`; на основном
  домене плавающая кнопка открывает корректную форму с активной кнопкой отправки.
- PASS: прайс, исходный R117, аналитика, настройки заявок и новогодняя страница
  совпадают с сохранённым выпуском. API здоров, публичный маршрут принимает POST.

Реальная заявка пользователя повторно не отправлялась. Все отправки агента —
виртуальные, в локальную базу в памяти, без сообщений MAX.
Доказательства — `concepts/bath-choice/deploy-review/phone-before-fix.json`,
`lower-form-four-channels.json`, `floating-callback-fixed.json`,
`callback-fix-postcheck.json`, `floating-callback-live-check.json` и снимки рядом.
