  загружен на сервер. Окно `DachaPar - CRM audit` требует sudo пользователя deploy.
- Проверить зарегистрированные цели и read-only доступ к API счётчика 113675581,
  фактические флаги Вебвизора/clickmap и соответствие кнопок целям.
- Проверить политику согласия на историю посетителей, срок хранения и возможность
  отказа без блокировки формы. Согласие на заявку не заменяет согласие на историю.
- Проверить точные правила Caddy для `/go/` и `/api/analytics/`.
- Выполнить успешный вход владельца в существующий manager API. Поскольку старого

  с сохранением хэшей; привязка владельца — только по проверенной аутентификации.

## План обратимой миграции после PASS

1. Забрать точные действующие серверные модули в контролируемую ветку, сохранить
   контрольные суммы и тесты существующей авторизации/лидов/MAX.
2. Аддитивные staff/roles/permissions/sessions/audit таблицы, отдельная таблица
   классификации лидов с предыдущим рабочим состоянием. Не менять snapshot_json
   и уникальность request_id. На время отката старая схема остаётся читаемой.
3. Серверные разрешения на каждом endpoint; отзыв сессий при блокировке/смене роли,
   защита последнего owner_admin, CSRF, тесты 403 и IDOR.
4. Конструктор ссылок с внутренними allowlist-маршрутами и раздельными техническими
   переходами/подтверждёнными визитами. Затем разрешённые события и привязка к лиду
   через проверенный сервером контекст, не visitor_id из произвольного body.
5. Собственные отчёты first/last non-direct/conversion touch независимо от Метрики.
   Продажи — подтверждённые CRM, не предварительная стоимость выбранной бани.
6. Отдельные отключаемые флаги трекинга, RBAC, отчётов. Отдельный откат web/API;
   восстановление БД допустимо только по плану с учётом новых заявок после снимка.

Пароли, cookie, токены, хэши паролей и данные клиентов в этот отчёт не включаются.

- Окно проверки входа не создаёт пользователей. Нового менеджера нельзя считать
  созданным по факту ввода телефона/пароля в этом окне.
