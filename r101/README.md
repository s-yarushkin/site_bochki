## Сборка

Из корня implementation, Python с Pillow и BeautifulSoup (в этом workspace bs4 находится в `.local/python`):

```powershell
python r101/build.py
python r101/verify.py
node --test tests/r101.test.mjs
```

Сборка в `output/r101-site`; публичная база `web/` и API не редактируются. Все цены читаются из оригинального прайса. Тесты нового клиента используют изолированную `.local/api-baseline`, без токенов и живых обращений.

## Локальный просмотр

```powershell
$env:DP_TEST_PORT='4174'
$env:DP_WEB_ROOT='output/r101-site'
node scripts/dev-server.mjs
```

Открыть http://127.0.0.1:4174/. Локальный сервер слушает только loopback, работает с SQLite в памяти и заглушкой уведомлений. Реальные MAX/Telegram не вызываются. Без API baseline можно использовать обычный статический сервер корня сборки: тогда форма честно сообщает, что отправка недоступна.

## Что важно при выпуске

Это кандидат: robots запрещает индексирование, маркетинговые страницы содержат noindex. Не переносить его вслепую на production. Выпуск должен отдельно включить индексирование, проверить ссылки, сохранить current WEB для отката и только затем переключить публичную оболочку. Старый R100-remote.py к этому кандидату не применять: у него другой baseline.

Кабинет manager.html, его JS/CSS, юридические документы, site-settings и ценовые модули защищены хешами. API и приватные данные не входят в изменения R101. Публичные модели/размеры, а также `?size=` остаются пригодны для рекламных посадочных. Не создавать рекламные кампании по недоказанным обещаниям панорамного остекления в Комфорте.
